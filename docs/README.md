# Docs · 学习产物目录

这里放**你的学习产物**，不是计划文档。

计划类文档（42 天大纲、任务卡、学习契约、清单体系）留在 WorkBuddy 工作区，随时会改。
这里的东西**跟代码一起进版本库**，将来是作品集的一部分。

## 目录规则

| 目录 / 文件 | 放什么 | 频率 |
|---|---|---|
| `Journal/` | 每日 6 行笔记，文件名 `YYYY-MM-DD.md` | 每天 |
| `DesignDecisions.md` | 设计判断台账（"我为什么这么设计"） | 有感就加 |
| `Bugs/` | 踩坑记录，文件名 `YYYY-MM-DD-英文短名.md` | 每踩一个坑 |
| `Experiments/` | 实验代码结论与数据（bench 数字、布局打印） | 每周 |

**文件名一律用 ASCII**（日期 + 英文短名），内容写中文。否则跨平台和 git 会有编码问题。

## 和 `PROGRESS.md` 的区别

- `PROGRESS.md`（项目根目录）：**做了什么**。教程进度流水账，给未来的自己看上下文。
- `Docs/Journal/`：**理解了什么**。有档位、有验证方式、有悬着的疑问。

两份都要，不要合并。混在一起的结果是两个目的都达不到。

## 每日笔记的六行

收工时填，格式固定，多一行都不要：

| 概念 | 代码里的对应物 | 我怎么验证的 | 档位 |
|---|---|---|---|

- **概念**：今天真正搞懂的一个点，一句话
- **代码里的对应物**：落到具体的类名 / 函数名 / 行
- **我怎么验证的**：跑了什么、看到了什么输出
- **档位**：【猜】没依据 / 【依据】读过文档或源码 / 【验证】自己跑过有输出

**六行里至少要有一行是【验证】。** 全是【猜】和【依据】，说明今天只输入没输出。

再加一栏 **「悬着的疑问」**：至少 1 条，写清"明天怎么验证它"。这一栏是第二天开工的入口。
